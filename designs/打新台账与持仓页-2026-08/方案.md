## 1. 打新独立台账（脱离股票识别侧）

打新的本质是「一笔钱出去，几周后一笔钱回来」，代码/行情/持仓机制全是噪音
（申购代码无行情导致市值显示 0、上市换代码等一整类问题的总根源）。
改为独立记录类型，与 trades 平行：

### 数据结构

```js
// state.ipoRounds: 一轮打新 = 一次中签的完整生命周期
{
  id: 'ipo_xxx',
  name: '长鑫科技',        // 纯文本，用户手填，不做任何代码识别
  buyDate: '2026-08-11',   // 缴款日
  shares: 10,
  costPerShare: 100,       // 发行价；总成本 = shares × costPerShare
  sells: [                 // 支持分笔卖出；剩余股数 0 即一轮结束
    { id: 'ips_xxx', date: '2026-08-20', shares: 10, price: 130, cashTrackedCny: null }
  ],
  cashTrackedCny: null,    // 买入腿的现金追踪（与 trades 同机制）
  note: '',
  createdAt, updatedAt
}
```

### 行为

- **记一笔 → 打新**：抽屉两态。有在途轮 → 顶部列出（名称 · 剩余股数 · 成本 · 已持天数），
  点一轮进卖出表单（日期 / 股数默认剩余 / 每股价格）；任何时候下方可新建
  （名称 / 日期 / 股数 / 每股成本 / 备注）。无费用、归入、类型、代码识别。
- **现金**：买入腿 −总成本、每笔卖出腿 +卖出额，走 `adjustCashForRecordChange`
  同一套（每条腿各自带 cashTrackedCny）。
- **净资产**：在途轮按「剩余股数 × 成本价」计入资产（修复现在打新期间净资产
  凭空少一块的失真）。持仓页在有在途轮时显示一行「打新在途 ¥xxxx · N 轮」
  （非默认态标记，无在途时整行消失）——钱在那儿，看不见会让净资产对不上账。
- **年度复盘**：打新收益 = Σ(卖出额 − 卖出股数 × 成本价)，按卖出日期归年。
  替换现有 isIpo-trades 口径。records 页三段流水加第四段「打新」（无记录不显示）。
- **交易抽屉回退**：删「类型 常规/打新」段、转债/申购代码自动拨挡、打新精简态；
  `sanitizeTradeEntry` 保留 isIpo 字段容忍旧数据，UI 不再产生。
  annals.js 的 isIpo 传染/轮次逻辑删除，换 ipoRounds 聚合。
  记一笔的「打 新」入口保留，改为打开新台账抽屉。
- **迁移**：启动时一次性把 `isIpo === true` 的 trades 转成 rounds
  （用户现有 733642 买入 → 一条在途轮，name 取 note 或代码，原 trade 删除并写墓碑，
  cashTrackedCny 平移，不动现金余额）。迁移幂等、有测试。
- **同步**：snapshot 加 `ipoRounds` 字段（版本号不动，applySnapshot 容忍）；
  merge 按 id 并集 + `recordTombstones.ipoRoundIds` 墓碑过滤（对齐 trades 的做法）。
